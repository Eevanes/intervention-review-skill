# Intervention Review · 介入判断

**让支持发生在恰当的时候，也让团队保有自己解决问题的空间。**

Intervention Review 是一个面向助教、导师和项目负责人的 AI Skill。它帮助你从项目进展、团队协作和求助信息中识别真正需要关注的事项，判断是否需要介入、采取什么方式，以及后续如何复查。

它关注的不是生成一份更长的消息摘要，而是回答：**现在需要谁做什么，为什么，以及怎样判断帮助是否有效？**

## 适用场景

- 学习项目或实战营：识别求助、任务卡点和临近交付的关键依赖。
- 团队协作：区分可以自行解决的分歧、需要澄清的问题与需要负责人协调的事项。
- 项目跟进：结合已确认的目标、里程碑和近期进展，确定复查重点。
- 个案复盘：根据后续证据判断支持是否有效，调整强度或结束跟进。

## 工作方式

Skill 围绕六个问题组织判断：**证据、目标差距、等待代价、自解空间、支持增益、介入比例**。它给出五种结论之一：立即介入、提供支持、继续观察、补充证据或无需行动；再从 L0 观察到 L6 人工升级中选择最低有效强度。

输出将事实、判断和建议分开，并尽可能说明下一步、成功标准和复查条件。群聊安静、没有回复或读取失败本身不构成问题证据；背景资料也不能替代当期事实。

## 安装与使用

1. 将 [`intervention-review/`](intervention-review/) 整个目录安装到支持 `SKILL.md` 的 Agent skills 目录，保留其中的 `config/` 文件夹。
2. 在项目工作目录创建 `.intervention-review.json`，按需覆盖 [默认配置](intervention-review/config/default.json)；也可先不创建，直接使用默认值。配置中只写已授权的来源名称或路径，凭据使用宿主的安全配置方式，不放入此文件。
3. 调用 `intervention-review`，提供项目目标、授权范围、近期事实和已有行动。例如：

   > 请使用 intervention-review，结合本周项目目标与已提供的会议纪要，判断哪些事项需要我跟进。请列出证据、下一步和复查条件。

4. 检查输出和证据；需要对外沟通时，先审核草稿并按宿主要求授权执行。

配置是给 Agent 读取的行为约定。Skill 自身不会自动连接数据源、注册定时任务、发送消息或保存状态；这些需要宿主提供相应工具和授权。

## 配置

配置文件为 JSON。Agent 从 Skill 目录读取默认配置，再读取当前工作目录的 `.intervention-review.json`（若存在）；对象按字段递归合并，数组整体替换。当前请求中的明确要求优先于配置，但不能扩大授权或覆盖安全边界。完整字段与示例见 [配置说明](intervention-review/config/README.md)。

| 配置项 | 用途 | 默认 |
| --- | --- | --- |
| `project` | 项目目标与时区 | 目标留空；`Asia/Shanghai` |
| `sources` | 标注本项目允许使用的资料来源 | 空列表 |
| `review` | 复查窗口与单次建议数量 | 24 小时；最多 2 个下一步 |
| `notifications` | 值得主动提醒的判断类型与去重原则 | 仅有行动价值的新事项 |
| `delivery` | 审核方式 | 只生成审核稿；对外发送须另行授权 |

## 判断原则

- **证据优先**：给事实标注来源和时间，缺失时先核实；不推断人格、动机或能力。
- **最小有效支持**：先看团队是否有负责人和可行下一步，避免不必要的催促或代做。
- **低打扰**：没有需处理的新变化时，不主动发送“无事”提醒；用户主动询问仍应正常答复。
- **人工负责**：高影响事项交有权限的人处理；建议、草稿和已执行行动清晰区分。
- **复查闭环**：记录成功标准和复查条件，根据新证据继续、调整或关闭。
