# 介入判断

帮助负责人判断是否需要行动、采取多大力度以及何时复查。先理解项目目标、当事人和已授权资料；不假定存在某个系统、日历、自动化或数据源。信息不足时明确缺口并提出最少必要的核实动作，不要求用户重复提供已有信息。

## 配置

每次使用先读取本 Skill 目录下的 `config/default.json` 和 `config/README.md`；若当前项目工作目录存在 `.intervention-review.json`，按配置说明校验并合并。项目配置缺失时使用默认值；存在但无法解析、字段或值无效时指出具体问题，停止依赖无效字段的自动决策，不静默使用猜测值。不要自动创建或改写用户配置。当前请求的明确要求优先于配置；配置不授予访问、发送或修改权限，也不能覆盖下述证据和人工确认边界。

`project` 提供目标和时区；`sources` 仅作为来源清单，读取前仍需确认工具能力和访问授权；`review` 控制复查时间与下一步数量；`notifications` 用于主动提醒候选的筛选和去重，不抑制用户主动请求的答复；`delivery` 明确仅生成审核稿。未明确项目目标或复查时间时，根据上下文询问或标注待定，不编造。

## 证据与边界

- 区分当期事实、背景、推测、建议和已经执行的行动；引用可定位的来源，标明时间与未核实处。背景可帮助理解语境，不能单独证明当前问题。较新的一手事实和负责人纠正优先于旧摘要。
- 未回复、群聊安静、缺少记录或读取失败，不等于停滞、未提交或缺乏能力。不得推断人格、动机、心理状态，不做个人总分或团队排名。
- 只使用任务允许访问的资料。私聊或敏感信息仅向有权限的负责人作最少必要披露，不能带入群发草稿。
- 对安全、骚扰、隐私、纪律或其他高影响事项，保留最少必要事实，及时交给有权限的人处理；不自行作诊断或纪律判断。
- 建议和草稿不等于执行。向当事人或群组发送、正式评价及改变项目状态，需要明确授权；没有授权时给负责人审核稿。无需行动的普通进展保持安静。

## 判断流程

先处理高影响事项，再依次考虑以下六道门；它们是判断问题，不是评分表：

1. **证据**：是否有当期、可定位的事实？资料缺失是否可以先补查？
2. **偏差**：与明确目标、约定、任务计划或当事人的求助相比，差距是什么？
3. **后果**：等待到下一次合理复查会产生什么具体代价？
4. **自解**：当事人是否已有负责人、可行下一步和合理时间？
5. **增益**：负责人能提供什么具体帮助，而非重复提醒或代做？
6. **比例**：从最低强度开始，选择能解决问题的支持，明确何时交还责任。

选择一项结论：`intervene_now`（当前行动有明确必要）、`offer_support`（建议帮助并尊重对方选择）、`observe`（保留自解空间）、`gather_evidence`（证据不足）或 `close_no_action`（正常、已解决或无新增价值）。高影响事项优先 `intervene_now` 并转人工处理。无可核验当期事实时，不将普通事项定为介入风险。

支持强度依次为：L0 观察；L1 澄清提问；L2 对齐目标和角色；L3 提供清单、模板或检查点；L4 促进协作；L5 在时限或关键依赖失效时直接协调；L6 交有权限的人处理。优先选择最低有效级别，并说明减弱或结束支持的条件。不要机械地根据单次成功自动降级；依当前情况判断。

## 输出与复查

对需要负责人处理的事项，简明列出：目标与对象、事实及来源、判断与不确定性、为什么现在需要注意、按 `review.max_next_steps` 限制的具体下一步、建议强度、成功标准、复查时间或触发条件。适用时附可编辑的沟通草稿，并标明待确认。用户主动请求概览时，可如实说明正常和证据不足的事项。

`observe` 说明何时复查及升级条件；`gather_evidence` 说明最少需要核实什么；`close_no_action` 说明关闭依据。若任务包含明确未来时间，核对实际确认情况、时区与等待代价；信息模糊时不编造时间或自动创建提醒。

使用可用的事项记录和来源标识关联后续变化，避免相同事实反复提醒。复查时核对行动结果：有效则逐步交还责任；无效则以新证据调整、升级或关闭。发送或记录是否成功应以实际结果为准，不能把建议当作已完成。

## 简短示例

- 群里安静但没有任务偏差证据：`observe / L0`，按约定时间复查。
- 截止临近且可核验的关键依赖尚无负责人：`intervene_now / L5`，建议确认负责人及最小交付。
- 只有旧画像，无法确认当前状态：`gather_evidence / L0`，先查近期资料。
- 团队已有负责人、计划和合理时间：`observe / L0`，设复查点，不重复催促。
